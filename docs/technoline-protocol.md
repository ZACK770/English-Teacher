# פרוטוקול טכנוליין שנמדד

היישום תומך רק בפורמט שנצפה בשיחת אמת. הוא אינו מנסה לנחש פורמטים חלופיים.

## פתיחה

המסגרת הראשונה היא טקסט JSON:

~~~json
{
  "type": "start",
  "callId": "...",
  "caller": "...",
  "system": "...",
  "token": "2614d922d06b4f",
  "format": "pcm16;rate=8000;ch=1"
}
~~~

token הוא מזהה הערוץ ולא סוד האימות. האימות האמיתי נעשה בכותרת:

~~~text
Authorization: Bearer <TECHNOLINE_BEARER_SECRET>
~~~

## אודיו

לאחר מסגרת הפתיחה מתקבלות מסגרות בינאריות:

- PCM חתום 16-bit little-endian.
- מונו.
- 8,000 דגימות לשנייה.
- 320 בתים בכל 20ms.
- ללא WAV, JSON או Base64.

Gemini מקבל PCM16LE ב־16kHz ומחזיר PCM16LE ב־24kHz. ההמרה הזו מתבצעת רק
בתוך השרת. כלפי טכנוליין הפורמט נשאר 8kHz.

## סיום

השרת מקבל מסגרות טקסט מסוג stop, hangup או end כסיום. ניתוק WebSocket מסיים
גם הוא את המפגש. פקודות יזומות להעברה או ניתוק אינן נשלחות עד לקבלת מפרט
מאומת מטכנוליין.
